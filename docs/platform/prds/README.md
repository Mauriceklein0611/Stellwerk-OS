# PRDs – Index

Product Requirements Documents werden **nur für größere Produktbereiche** erstellt und
**erst, wenn ihr Meilenstein aktiv wird** – keine leeren Zukunfts-PRDs. Vorlage:
[../../templates/prd-template.md](../../templates/prd-template.md).

Ein PRD beschreibt Problem, Zielgruppen, Use Cases, Nutzerergebnis, fachliche
Anforderungen, Nicht-Ziele, Erfolgskriterien, Risiken und offene Produktfragen.
**Technische** Lösungsentscheidungen gehören in Architektur/ADRs, nicht als zweite
Wahrheit ins PRD.

## Kandidaten (erst bei aktivem Meilenstein)

Erster echter Agent (v0.2, derzeit über [Release Charter v0.2](../release-charters/v0.2.md)
abgedeckt – ein separates PRD ist hier nicht nötig), HITL-Workflows (v0.3), Leitstand
(v0.6), IDP (v0.7), RAG (v0.8), Flow (v0.9).

## Aktuelle PRDs

_Noch keine._ Der aktive Meilenstein v0.2 ist über das Release Charter beschrieben.
